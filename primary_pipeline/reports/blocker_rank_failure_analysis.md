# Blocker rank-failure analysis

Benchmark: the existing deterministic split from the previous phase (`blocking/artifacts/benchmark_queries.json.gz`). It has 20,000 development queries (69,268 true pairs) and 7,500 untouched confirmation queries (26,066 true pairs). Every retrieval searches **all** same-country training S2 and S3 records (10.32M in total), per source. Only the development split was used for diagnosis and selection.

## Why the previous blocker stopped at 79.7%

The previous `RRF(address_char, name_char)` blocker ran in an environment without scipy or sklearn. It therefore used an approximate inverted index limited to 6 selected features per query. The EDA had already shown exact character TF-IDF reaching 94.7% at k=50 on 120 queries. The gap was an **implementation limit, not a data limit**. This phase uses exact sparse TF-IDF with hashed features (`HashingVectorizer`, 2^22 buckets, no vocabulary dictionary) and scipy sparse matmul per query batch.

## Findings

* **High multiplicity is not a blocking failure** with a proper ranker. The mult=4+ and mult=6+ pairs sit at the same ≤20 rates as mult=1. The previous "high multiplicity" miss category was an artefact of the global cap of 150 over fused channels. Per-source top-k (each S1 has on average about 1.7 matches per source) removes it. Dynamic caps were therefore **not justified** and were not built.
* The two structural gaps are **non-Latin target names** (3.37% never generated) and **targets without an address** (8.15%). The former led to transliteration and the latter to a missing-address name index; both were measured in `rescue_channel_analysis.md`.
* Short and generic names are not a problem for the combined channel (96.3% within ≤20), because the address carries the discrimination.
